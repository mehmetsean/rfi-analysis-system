# rfikit spec (v0.1 citation extraction, with the v0.2 to v0.4 plan)

Repository: rfi-analysis-system. Package, import and CLI name: rfikit. This rebuild replaces the 2025 prototype script (see "The prototype").

## Problem
A request for information (RFI) is a written question from a contractor to the design team on a construction or utility project. Many RFIs turn on a standard: which edition of IEEE C57.12.00 applies, whether NESC Rule 232 covers a crossing, whether an ASTM A123/A123M coating meets the spec. A team that wants to know which standards come up most, which RFIs repeat an earlier question and what kind of issue each one raises reads the log line by line.
rfikit reads an RFI export on the user's machine or in a static browser page, so the exported log does not have to leave that machine. Version 0.1 finds standard citations and normalizes each to a designation key. Version 0.2 adds an issue type with a stated reason and groups of recurring questions. Each task will ship with precision and recall measured on labeled synthetic data next to a simple baseline, and the scripts and seeds to rerun every number will be in the repo.

## User and buyer
- Document control and engineering teams at EPC firms, utilities, owner's engineers and construction managers who export RFI logs to CSV and want citation counts, repeat questions and issue types without uploading project text.
- Data and analytics people who want a tested example of span extraction, text classification and near-duplicate grouping with an honest evaluation.
- Money path: a paid commercial license per company, paid setup (column map, aliases, issue types and keyword rules tuned on a client's own export, run on the client's machine) and paid support.

## MVP (v0.1): citation extraction
Python 3.11+, standard library only at runtime, so the same wheel runs in Pyodide with no extra packages. CLI: `rfikit extract notes.txt` (citations as CSV; the column value is "text" for a text file and the column name for a CSV), `rfikit analyze rfis.csv --out results/` (columns rfi_id, subject, question, optional response; other names through a JSON column map), `rfikit generate --seed 42 --n 600 --out data/`, `rfikit evaluate data/ --written heldout/`.

1. Extraction. An anchor scan finds body tokens; a grammar per body reads the designation in a bounded window after the anchor. Each citation has its column, span, text, clause offsets, an inferred flag and a Designation (body, co_bodies, doc_type, number, part, year, suffix, clause) with a full key and a base key. Only designations and clause numbers are output, never titles or standard text.

| Body | Anchor forms | Designation after the anchor | Key example | Hard negatives (not citations) |
|---|---|---|---|---|
| IEEE | IEEE, IEEE Std | optional C, number with dotted levels (C57.12.00, 1547.1, 80), amendment letter, -YYYY | IEEE C57.12.00-2015 | IEEE Transactions, RFI-1547, 1547 kVA |
| NESC | NESC, IEEE C2, ANSI C2; bare Rule or Table only when the RFI cites NESC elsewhere | edition (2017 NESC, NESC-2017, C2-2017); Rule 232B1a, Table 232-1, Section 9 | NESC 2017 Rule 232B1 | Rule 12 of the contract, Room 232, sheet E-232-1 |
| IEC | IEC, IEC TS, IEC TR | five-digit number, part levels (61850-7-4), :YYYY, +AMD1:YYYY | IEC 60076-1:2011 | IP65 alone, drawing 60076-1 |
| ANSI | ANSI not joined to another body | letter and dotted number (C84.1, C12.20, Z535.4), -YYYY | ANSI C84.1-2020 | ANSI 61 gray, ANSI Class 150, ANSI D size sheet |
| ASTM | ASTM | letter A to G and number, metric twin (/A123M), -YY, revision letter, (reapproval year), e1 | ASTM A123/A123M-17 | A36 without ASTM, part A123-4567 |
| NEMA | NEMA | letters and number (TC 2, MG 1, WD 6) or three digits (250), -YYYY | NEMA TC 2-2020 | NEMA 4X, NEMA 3R, NEMA 5-20R, NEMA Size 2, NEMA Premium |
| Joint and alias | ANSI/IEEE, ANSI/NEMA, IEC/IEEE, IEEE/IEC, IEEE C2, ANSI C2, ANSI joined to any other body | the grammar of the body chosen by the precedence rule | IEC/IEEE 60255-118-1:2018 is IEC 60255-118-1:2018, co_bodies IEEE | ANSI/TIA-568 (outside the six bodies, nothing emitted) |

Precedence, applied in this order: (1) C2 after IEEE, ANSI or IEEE/ANSI is NESC, with the edition from -YYYY ("IEEE C2-2017" is NESC 2017). (2) ANSI joined to a body outside the six (ANSI/TIA, ANSI/ISA, ANSI/ASME) emits nothing. (3) Otherwise the first developing body written is the body and the rest, ANSI included, go to co_bodies: ANSI/IEEE C37.2 is IEEE, IEC/IEEE is IEC, IEEE/IEC is IEEE. Keys never include co_bodies, so ANSI/IEEE C37.2 and IEEE C37.2 share a key. (4) The scan resumes at the end of the previous match, so matches never overlap and an anchor inside a match is not read again.
Span convention, one rule: start and end cover the designation only, from the first character of the body token (of the number for a list item, of the edition when it comes first as in "2017 NESC") to the last character of the number, part, year or suffix. A clause has its own clause_start and clause_end and is scored in the full key, never in the strict span. The one citation with no designation text, an inferred bare NESC rule or table, takes its clause offsets as its span. Example: in "2017 NESC Rule 232B1" the span is "2017 NESC", the clause is "Rule 232B1", the full key is "NESC 2017 Rule 232B1" and the base key is "NESC Rule 232B1". "NESC-2017" and "C2-2017" are spanned as one whole token. The base key drops edition and suffix: for NESC, whose number is always C2, it keeps the rule, table or section; for every other body it is body, document type (IEC TS or TR, as in "IEC TS 61850-7-4"), number and part. A bare NESC rule or table that takes its edition from nowhere has a key with no edition ("NESC Rule 234B"), because one RFI can cite two NESC editions and an edition cannot be inherited.
- Clauses attach when clause, section, sec., para, table, figure, annex or rule plus an id follows within 40 characters, or comes before as in "Section 5.3 of IEEE 80". Section, sec. and para become clause for every body except NESC. NESC keeps its own words, Rule, Table and Section, because they are part of its numbering ("Sec." becomes Section). Keys use the capitalized forms Clause, Table, Figure, Annex and Rule, for example "IEEE 80 Clause 5.3" from "Section 5.3 of IEEE 80" and "IEEE 80-2013 Table 3" from "Table 3 in IEEE 80-2013". A clause followed by "of" or "in" and a body binds forward; otherwise the nearest preceding designation within 40 characters takes it. A clause belongs to at most one citation, and the scan resumes at the end of the designation, not of the clause.
- List continuation: in "IEEE C57.12.00, C57.12.90 and C57.91" the later numbers inherit the body when they fit its grammar. List items and bare NESC rules are marked inferred.
- Cleanup is a one-to-one character map (Unicode dashes and no-break spaces to ASCII), so offsets in the cleaned text are offsets in the original. Nothing is joined or deleted: where a line break falls between body and number or after "." or "-" inside a number, the grammar skips the line break and any spaces, the span covers them, and the key is built from the parsed parts of the match. Missing or extra spaces ("IEC60076-1", "ASTM A 123") and any letter case are accepted. Misspelled bodies ("IEE 1547") and letter O for zero are not repaired in v0.1 and are measured as misses by noise class.
- Offsets count Unicode code points (Python string indices). The demo converts them to UTF-16 units at the Pyodide boundary.
- Other bodies (NFPA, UL, ASME, ISA, TIA, CSA, EN) are not extracted. Their labels are marked out of scope and are never misses. A prediction that overlaps an out-of-scope label counts as a false positive of kind out_of_scope, reported on its own line.

2. Synthetic labeled RFIs in rfikit.synth, built in two PRs. PR 4a, in v0.1, writes the RFIs with citation, negative and noise labels. PR 4b, just before v0.2, adds the issue type and group labels and the recurring-question paraphrases, with its own tests (one issue type per RFI, group ids match the generator record). The generator calls only random.Random.random() and derives choices, shuffles and integers from it with no math.log or other libm calls, because the Python random module documents that the random() method gives the same sequence for a seed across Python versions. Files will be byte-identical per seed and version on Python 3.11 to 3.14 and under any PYTHONHASHSEED, checked by the golden test in the test plan. synthbiz output conventions: manifest.json with sha256 per file and "synthetic": true, README.txt in every folder, labels kept apart from inputs. Projects are codes (P-0412), disciplines generic (substation, distribution line, solar plant, commercial building), people role ids (CONTRACTOR_PM). No real company, facility, project or person, and nothing from any employer.
- Designations come from a catalog of designation and clause numbers written for this repo to match published designations (identifiers only, not checked against the standards) and from invented numbers that fit each grammar; labels mark which. Templates never state what a standard requires.
- Hard negatives labeled by kind: the table's list plus part, drawing, room and RFI numbers, dates, kVA ratings and spec section numbers (26 05 26). Noise labeled by class: line breaks inside designations, spacing, case, Unicode dashes, misspelled bodies, list continuations. Label offsets are updated through every noise step.
- Template families per issue type with slot synonyms, clause order changes, optional greetings and responses. Each template has a template_id and a family, A or B (about a quarter per issue type is B). Family B is held out from training and numeric tuning, not from the author, who writes the grammar, the templates and the v0.2 rule phrase lists. The phrase lists are written from family A templates only, and family B goes in its own commit before any tuning.
- A recurring question is k paraphrases of one seed question under one group_id. Outside groups no (template, slot values) pair repeats, and each RFI outside a group gets its own unique group_id.
- Labels come from the generator's record of where it inserted each item, never from running the extractor.
3. Written held-out set in heldout/: about 80 RFIs written one by one for this repo, not by the generator, with at least 150 in-scope citations (15 or more per body), 40 hard negatives, an issue type per RFI and 12 recurring groups; marked synthetic data. A single annotator labels it per docs/annotation_guide.md, with no agreement measure. It is committed with its sha256 before the extractor and rules are tuned, which the git history shows; later label fixes go to heldout/CHANGES.md.

`analyze` scans subject, question and response and writes citations.csv, analysis.md and analysis.html (top base keys, counts per body and per RFI, measured rates labeled "measured on synthetic data") and README.txt with the notice and disclaimer.

## v0.2 design: issue types and recurring questions
Designed now because the generator labels them; built after v0.1 ships. analyze then adds rfis.csv (issue type, method, reason, group_id) and groups.csv.
- Issue type, one label per RFI from subject and question only (no response exists at triage time): design_clarification, missing_information, document_conflict, substitution_request, field_condition, standard_applicability. Methods: majority class (baseline); keyword rules (ordered phrase lists written from family A templates; the reason names the phrase that fired; no match is an abstention, scored as wrong and counted); multinomial naive Bayes in the standard library (unigrams and bigrams, Laplace smoothing alpha, citation spans replaced by a body token such as cite_ieee, numbers masked, vocabulary limited to tokens seen at least twice and capped at 20,000 by count with ties by token string, top weighted tokens as the reason). Naive Bayes trains on family A rows of the train seeds only and ships as JSON, so the demo never trains.
- Recurring questions: TF-IDF on subject and question (sublinear tf, citations replaced by their base key token, so "IEEE Std C57.12.00-2015" and "IEEE C57.12.00" match), unit vectors, pairs with cosine at or above t - 1e-9 joined by union-find. Union-find is single linkage, which can chain, so the report prints the largest group. Grouping runs on one input file or one seed corpus at a time; groups never span files.
- Blocking is exact prefix filtering, chosen over all pairs (O(N^2)) and MinHash LSH (approximate, needs tuning). Tokens have one global order: document frequency ascending, then token string. Each vector's prefix is the shortest prefix whose remaining suffix has L2 norm below t - 1e-9. Only prefixes are indexed and whole vectors probe. If x shares no token with prefix(y), cos(x, y) <= ||suffix(y)|| * ||x|| < t - 1e-9, so every pair at or above t - 1e-9 is found and the result equals all pairs with the same test. A compare iterates the smaller sparse dict and looks each token up in the larger one, O(min(|x|, |y|)). Zero-norm vectors (no tokens after cleaning) are skipped and become singletons. A budget counts distinct candidate pairs, default 50 x N, and raises BudgetExceeded with the count.

## Design
Constraints: runs in Pyodide, no network calls, methods never see labels, extraction linear in text length on hostile input, and in v0.2 grouping below all-pairs cost without losing a pair above t.
Options for extraction: per-body regexes over the whole text (the prototype: no spans, no normalization, "Rule 232" matched anywhere; kept as a baseline); a learned sequence tagger (needs real labeled text, which is not public, and would only learn the generator's grammar); chosen: anchor scan plus per-body grammar with no catalog lookup, so unseen standards are found. For v0.2 classification: rules and naive Bayes (closed-form training, inspectable weights); logistic regression and a local model come in v0.4 behind the same Classifier protocol.
Modules: types (frozen dataclasses), textnorm (character map, tokenizer), cite, synth, io (CSV and text, column map, BOM, row and field caps), evaluate (the only module that reads labels), report (CSV, Markdown, HTML; cells starting with =, +, - or @ are escaped), analyze, cli; classify and group in v0.2. cite depends only on types and textnorm, so it can ship alone later; cite, classify and group import neither synth nor evaluate.
```python
def extract(text: str, column: str = "text", context: CiteContext | None = None) -> list[Citation]: ...
def extract_rfi(rfi: Rfi) -> list[Citation]: ...  # NESC context shared across columns
def parse_designation(raw: str) -> Designation | None: ...
def generate(seed: int, n: int, params: GenParams | None = None) -> Corpus: ...
def read_rfis(path: Path, column_map: ColumnMap | None = None) -> list[Rfi]: ...
def evaluate(data: Path, written: Path | None, plan: EvalPlan) -> EvalReport: ...
def write_analysis(out: Path, result: AnalysisResult) -> None: ...
class Classifier(Protocol):  # v0.2
    def predict(self, rfi: Rfi) -> Prediction: ...  # label, method, reason
def train_naive_bayes(rfis: Sequence[Rfi], labels: Sequence[str], alpha: float) -> NaiveBayes: ...  # v0.2
def group_rfis(rfis: Sequence[Rfi], threshold: float, budget: int | None = None) -> GroupResult: ...  # v0.2
```
Data model: Rfi(rfi_id, subject, question, response); Citation(column, start, end, text, designation, clause_start, clause_end, inferred); the attribute is named column, not field, to avoid clashing with dataclasses.field. Designation has key() and base_key(); Prediction(rfi_id, label, method, reason) and Group(group_id, rfi_ids, terms, citations) arrive in v0.2. Label files: labels/citations.csv (rfi_id, column, start, end, clause_start, clause_end, key, base_key, scope, inferred, catalog, noise_class), labels/negatives.csv (rfi_id, column, start, end, kind), labels/rfis.csv (rfi_id, issue_type, group_id, template_id, family). Seed roles (train, tune, report) live in the evaluation plan, not in the data.
Complexity (n characters, a anchors, window w = 96, L tokens per RFI, K phrases, T tokens, V vocabulary, C classes, N RFIs, p candidate pairs, S seeds, B draws): extraction O(n + a x w) = O(n), bounded quantifiers only, so no regex backtracking blowup; NESC context one more O(n) pass. v0.2: rules O(L x K); naive Bayes training O(T + V x C), prediction O(L x C); TF-IDF O(T), prefixes O(T log T), p is the sum of prefix posting lengths over probes, O(N^2) in the worst case (every RFI shares rare tokens), capped by the budget; each compare O(min(|x|, |y|)); union-find O(p alpha(N)). Scoring: span matching is a two-pointer sweep over sorted non-overlapping spans, O(g + q) per column for g gold and q predicted spans; pairwise grouping counts come from a contingency table in O(N), no pair list; bootstrap O(B x S).
Benchmark: benchmarks/bench.py writes docs/benchmark.md. v0.1: extraction precision, recall and characters per second for a naive baseline (body token plus the next token), the prototype regexes and rfikit. v0.2: grouping time, p and compares; all pairs and prefix filtering both run at N = 1,000 and 5,000 and must return the same pairs; N = 20,000 runs the filter alone and reports p. CI runs N = 300 to 1,000 with the equality assertion and no time limits.

## Evaluation design
- Seeds: report seeds 101 to 130, 600 RFIs each; train seeds 1 to 5 and tune seeds 6 to 10 serve v0.2 (naive Bayes, alpha, t). The extraction grammar has no numeric settings; the author develops it on seeds 1 to 10, family A. Before scoring, any report RFI whose cleaned subject and question text also appears in a train or tune seed is dropped, and the dropped fraction is printed. Every number is shown on three sets: family A on report seeds, family B on report seeds and the written set. Report seeds and the written set are scored once per release; grammar changes are made from seeds 1 to 10 only, and any change prompted by a written-set error is logged in heldout/CHANGES.md.
- Extraction: precision, recall and F1 at four levels: strict span (same column and offsets), overlap span (one-to-one by the sweep), full key (multiset of keys per RFI) and base key. Broken down by body, noise class, inferred vs explicit and catalog vs invented, with false positives per hard negative kind. A clause line reports precision and recall of clause offsets. The naive and prototype baselines are scored at strict and overlap span; their key levels print n/a, since neither normalizes. NESC gets its own line in that comparison, because the body token alone matches its strict span.
- Issue type (v0.2): per-class precision, recall and F1, macro F1, accuracy, confusion matrix and rule abstention rate for majority, rules and naive Bayes side by side.
- Grouping (v0.2): pairwise precision, recall and F1 against group_id, group count and largest group. Baseline: exact match on the cleaned subject.
- Intervals: on generated sets, a 95 percent percentile bootstrap over report seeds (2,000 draws, fixed RNG seed). It is an interval over generator draws, conditional on the template set, and says nothing about other templates or real text; it is printed beside the family A vs B gap. Written set: Wilson intervals for extraction precision and recall, false positives on hard negatives pooled over kinds (too few per kind), and issue type macro F1 with a bootstrap interval over RFIs only.
- Zero denominators: a precision or recall of 0/0 is n/a, never 0 or 1; F1 is n/a when either part is; macro averages skip n/a classes and print how many they skipped.
- src/rfikit/measured.json holds the full run and a CI block computed on a smaller fixed list (report seeds 101 to 103 and the written set, target under two minutes on a CI runner). scripts/make_measured.py --check recomputes only the CI block and fails CI when it differs; the full run is rebuilt before each release. scripts/reproduce_readme.py regenerates every README number.

## Limits
- The written set's dash noise uses U+2010, U+2011, U+2012 and U+2212 only, because the repository's text checks reject U+2013 and U+2014. The extractor's unit tests are to cover those two characters from escapes.
- The author wrote both the grammar and the generator. Recall on invented numbers shows the grammar does not memorize the catalog; it shows nothing about real formats the author did not think of. The written set is the closer test, with the same author and a single annotator.
- In generated data the issue type follows from the template, so a classifier can score well by recognizing templates. The family B and written numbers are the ones to read.
- Outside groups the generator never repeats a (template, slots) pair, so recurring-question labels are cleaner than in a real log.
- No real RFI log has been tested. Rates on real logs will differ.

## Non-goals
- rfikit does not say whether a standard applies, what it requires or whether a design complies. No standard text, titles or clause wording anywhere.
- No language models, PDF or OCR input, multi-label types, equipment tags or priority scores. The prototype's length-based priority score is dropped: no label exists to measure it.
- No project platform connectors, server, accounts or upload. English only.

## Demo plan
- Static GitHub Pages site in site/. Paste mode: paste RFI text, see citations highlighted with the body written inside each mark (not color alone) and a table of keys; a button loads a synthetic sample by seed. v0.2 adds the issue type with its reason. Results page: measured.json as tables for all three sets (per body, per noise class; confusion matrices and grouping from v0.2), labeled "measured on synthetic data".
- Pyodide core files and the rfikit wheel are served from the Pages origin, not a CDN, since pasted text may be real project text. A meta tag sets this CSP, and the browser test checks that Pyodide still loads under it: default-src 'none'; script-src 'self' 'wasm-unsafe-eval' 'unsafe-eval'; connect-src 'self'; style-src 'self'; img-src 'self' data:; base-uri 'none'; form-action 'none'. No inline script. Pages cannot send custom headers and a meta CSP cannot set frame-ancestors, so the page cannot stop other sites from framing it.
- Highlights are built from text nodes, never HTML strings. The browser test pastes text with an astral-plane character (written as an escape) before a citation and checks that the highlight covers the citation; it also fails on any request to another host.
- Design tokens from the synthbiz demo stylesheet. Keyboard use, a label on every control, wide tables scroll in their own box. The page must pass axe, show no console errors and no horizontal overflow at desktop and phone widths.
- examples/: seed 42, 200 RFIs, with its analysis files, marked synthetic data.

## Test plan
- Unit: table-driven cases per body (positives, every hard negative kind, each precedence step, clauses before and after, list continuation, NESC context present and absent, line breaks at each skip point), key and base key formats, Wilson bounds against known values. v0.2: rule order, naive Bayes against hand-computed probabilities on a tiny corpus, union-find.
- Property (hypothesis): text[start:end] equals the citation text and clause offsets lie inside the text; a random grammar-valid designation rendered in any supported style, inserted with blank space on both sides into filler drawn from a word list with no body tokens and no Rule, Table or clause words, extracts to the same key; spans never overlap; unrelated text added elsewhere removes no citation and shifts offsets exactly; adversarial input of digits, dots and body tokens runs in linear time: time on 2 MB over time on 1 MB stays under 3, with no absolute bound; defined scores stay in [0, 1], perfect output with at least one gold item scores 1, an extra false positive never raises precision. v0.2: naive Bayes posteriors sum to 1 and move by at most 1e-12 when training rows are reordered; filtered pairs equal all pairs; raising t only splits groups.
- Generator: identical bytes under two PYTHONHASHSEED values; golden bytes for seed 42 on Python 3.11 to 3.14 in the CI matrix; every label matches the text at its offsets after noise; no negative overlaps a citation; checksums verify; no family B template appears in a family A row; no (template, slots) repeat outside groups; group_ids outside groups are unique.
- Boundaries: cite, classify and group import neither synth nor evaluate; blanking label files and template ids changes no prediction. Regression: golden outputs for examples/ and golden metrics for a fixed seed list; each fixed bug adds a case. Input limits: malformed CSV, BOM, non-UTF-8 bytes, row and field caps give clear errors.
- CI: ruff, mypy --strict, pytest on Python 3.11 to 3.14, at least 90 percent line coverage on src/rfikit, make_measured.py --check, and the browser test in its own job.
